# POTUS data provenance

`../normal_wallets.csv` is a reproducible **synthetic** normal-wallet training
fixture generated by `backend/generate_data.py` with seed 42. It is not labeled
production activity. The model accepts its legacy columns or the canonical eight
model features; invalid training files fall back to a labeled synthetic population.

`real/monad_wallet_activity.csv` is the supplied aggregate RPC sample. Its original
rows have no recorded block range or timestamps, so the exact observation window
cannot be reconstructed. Keep it as a sample, not a complete 24-hour history or
a set of confirmed normal labels. The backend does not use this aggregate file
as the wallet feature source or as model training data. Both supplied CSVs were
preserved by this repair.

To collect a fresh sample without overwriting the supplied file, run from the
repository root after configuring `backend/.env`:

```sh
python -m backend.collect_monad_data --blocks 150 --output data/real/new_sample.csv
```

New samples include `source`, `first_scanned_block`, `last_scanned_block`,
`scanned_blocks`, `observation_seconds`, and `complete_24h_window` (false).
Transaction rates use the observed duration and are empty if that duration is
zero. Monetary amounts are accumulated as integer wei before conversion to MON.
A failed block scan stops collection before writing the CSV.

Live per-wallet features come from the configured RPC/Envio adapters. Full-day
features need indexed history; a bounded RPC sample is explicitly incomplete.
